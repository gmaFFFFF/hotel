# Помощники для взаимодействия с FusionCache

## Общие сведения

Пространство имен: `ZiggyCreatures.Caching.Fusion`.

Библиотека предоставляет несколько вспомогательных статических методов из класса FusionCacheHelpers

## Интеграция с обработчиками `gmafffff.starterKit.BusinessLogic.IQueryHandler`

Предоставляются два метода, создающие фабрику значений для кэша

* `GetHandleQueryAndCacheFactory` — для запросов `gmafffff.starterKit.Messaging.Query`, возвращающих 0..n значений;
* `GetHandleQuerySingleResultAndCacheFactory` — для запросов `gmafffff.starterKit.Messaging.Query`,
  возвращающих строго 1 значение;

### Использование

Передайте результат вызова методов в качества аргумента `factory` соответствующих методов `IFusionCache`

## Дополнительные перегрузки методов основных методов `IFusionCache`

### Кэширование сущностей с несколькими ключами

Для поддержки альтернативных ключей применяется следующий подход: сущность кэшируется по первичному ключу,
а альтернативные ключи кэшируют значение первичного ключа.

К методам `IFusionCache` добавлены перегрузки, принимающие в качестве аргумента словарь `altKeyGenerators`,
обеспечивающий генерацию альтернативных ключей.

Ключом словаря является строка названия ключа, а значением функция, которая вычислит значение ключа,
помещённого в кэш. Альтернативный ключ будет вычислен с помощью статической функции `KeyFormat`,
реализация по умолчанию которой может быть заменена.:
`(keyName, keyVal) => $"{keyName}:{keyVal}"`

### Кэширование множества значений в кэш с отдельными первичными ключами

Когда из БД возвращается много значений сразу, то текущий интерфейс кэша не позволяет задать каждому значению
свой первичный ключ.
Нельзя также проверить, что значение уже было в кэше.

Метод `TrySetAsync` помогает кэшировать все полученные результаты как индивидуальные значения.
При этом, если в кэше было сохранено значение с текущим ключом, то проверяется значение `LastModified` контекста.
