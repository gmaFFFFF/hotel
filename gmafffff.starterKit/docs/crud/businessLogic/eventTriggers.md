# События интеграции ограниченных контекстов (сигнальные события)

## Общие сведения

Для обмена сообщениями между ограниченными контекстами служат сигнальные события
`gmafffff.starterKit.Messaging.TriggerEvent`.

[!TIP]
Если обработка события предполагается в одном и том же ограниченном контексте,
то следует использовать события домена.

Реализовав интерфейс `gmafffff.starterKit.BusinessLogic.ITriggerEventToCommandTranslator<TT>`
можно определить какие дочерние команды необходимо выполнить в ответ на возникновение сигнального события.

Обработка дочерних команд осуществляется последовательно «в глубину».
Перед выполнением дочерняя команда будет полностью проверена на корректность и соответствие бизнес-правилам
так же как и обычная команда.

Для объединения нескольких обработчиков команд в единую транзакцию используется `TransactionScope`
со всеми вытекающими последствиями.

[!IMPORTANT]
Sqlite не поддерживает `TransactionScope`. Но чтобы код, использующий Sqlite,
можно было запустить следует вызвать на экземпляре `DbContextOptionsBuilder` метод
`.ConfigureWarnings(builder => builder.Log(RelationalEventId.AmbientTransactionWarning))`

## Использование

Для того чтобы один ограниченный контекст мог реагировать на действия другого необходимо:

* Добавить к событиям, возвращаемым из обработчика команд,
  событие, производное от `gmafffff.starterKit.Messaging.TriggerEvent`.
* Добавить интерфейс, реализующий `gmafffff.starterKit.BusinessLogic.ITriggerEventToCommandTranslator<TT>`,
  определив какие команды нужно вызвать в ответ на сигнальное событие.

## DI

Регистрация трансляторов сигнальных событий в команды в контейнере DI осуществляется вызовом
`AddTriggerEventToCommandTranslators` метода расширения `IServiceCollection`.
